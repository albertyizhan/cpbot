# cpbot · 车评与客户查档

独立 Telegram 机器人，使用自己的 Token、数据库和服务。与 xcbot 无数据库、接口或运行时连接。

配置模板使用 Go + PostgreSQL。已有 Python/SQLite 部署按[迁移指南](docs/GO_MIGRATION.md)切换。

## 开始使用

1. 首次配置时，将 `.env.example` 复制为 `.env`，填写 `BOT_TOKEN`、`SUPERADMIN_IDS` 和 `DATABASE_URL`。多个 Superadmin ID 用逗号分隔。旧 `SUPERADMIN_ID` 仍兼容，两项同时设置时取并集。
2. 确认 PostgreSQL 已有 `cpbot` schema 后，运行 `bash manage.sh build-go`，再以 root 运行 `bash manage.sh install` 安装并启动服务。启用「查车评」入口见 [Mini App 部署说明](docs/MINI_APP.md)。
3. 为已有集群设置服务时，私聊发送 `/admin`，进入「频道 / 群绑定」。给新群开通服务时，先按下文用激活码注册集群。
4. 按用途绑定目标。要发布车评，将机器人设为频道管理员并授予发布、编辑消息权限。仅「老师专帖」需要另行关联讨论组，并将机器人设为讨论组管理员。
5. 只需在群内查档时，将机器人设为群管理员并绑定「内部查档」即可。
6. 「添加老师」只发送一行老师名称。在「老师列表」选择老师进入详情，可修改名称、单独绑定或解除本人账号；本人账号为可选项，不影响客户写评、查评和主帖。
7. 客户填写车评，提交后直接进入限速发布队列，无需审核。Go 版的出击证明为选填。

## 多集群

升级后首次启动会把原有数据归入集群 `1`。原来的群绑定、老师、标签、车评、草稿、发布记录和私聊链接继续使用。

### 用激活码为群开通服务

1. **Superadmin 发码。** 私聊发送 `/start`，进入「Superadmin 后台 → 新建集群 → 集群授权」，点「生成授权码」并私下交给目标群的群主或管理员。码只显示一次，24 小时内可用一次，重新生成会作废旧码。
2. **群管理员注册。** 在机器人私聊的命令菜单选择 `/register`，或直接发送 `/register`。按提示另发一条消息提交激活码。
3. **设置管理群。** 把机器人设为该群管理员，发送群数字 ID 或 `@公开群用户名`。核验通过后才消耗激活码，进入该集群的「管理后台」。
4. **配置业务。** 按用途设置「频道 / 群绑定」，再设置「在群判定目标」或勾选其他「成员资格来源」。日后私聊发送 `/admin` 即可打开后台，管理多个集群时先选择集群。

### 集群管理员的权限

- **管理后台**向管理群和已启用的绑定群、频道及关联讨论组的当前群主或管理员开放。管理员可以修改本集群的名称，处理老师、车评、客户标签、业务绑定、成员资格和发布任务，并导出本集群备份。新增业务目标时，集群管理员和机器人都须在目标中担任管理员。只用于在群判定的目标授予普通成员资格。
- **Superadmin 后台**负责新建集群、发码和撤销授权。Superadmin 也可进入任意集群的管理后台，并执行覆盖恢复。此前的「输入授权码」入口仍可由 Superadmin 直接激活。

已有集群升级后继续服务。机器人会核验操作者当前的 Telegram 管理员身份。撤销集群授权会收回集群管理员的后台权限并停止查档、写评和发布，保留资料、任务及管理群。已有管理群的集群通过 `/register` 重新激活时使用原管理群。

每个集群独立管理老师、车评、客户标签、群绑定、在群判定目标和发布队列，共用同一个机器人和 superadmin 配置。频道、关联讨论组、查档群和判定目标按所属集群处理。同一个群或频道只能归属一个集群。

「在群判定目标」用于查询客户档案里的在群状态，并自动计入本集群的成员资格来源。也可在「成员资格来源」勾选其他群和频道。加入任一来源的成员可以使用本集群的私聊业务。机器人须在相应的群或频道担任管理员。

普通成员点击「写车评」「找老师」或「查学生」后，只有一个可用集群时直接进入，有多个时按显示名称选择一次。主帖写评和群查档的标签链接会直接核验链接对应的集群。「我的车评」直接列出本人在各集群提交的记录，并标明来源。集群备份包含已勾选的成员资格来源。

仅有一个集群且尚未启用成员核验时，沿用原有公开访问。单集群可通过「按判定目标核验成员」或勾选其他来源启用核验。启用核验或新增第二个集群后，普通成员按成员资格来源访问各集群。

### 删除老师与回收站

集群管理员在「管理后台 → 老师列表 → 老师详情」点击「删除老师」并确认。老师及其全部评价进入回收站，不再出现在老师列表或参与计分，也不能继续为其提交评价；老师账号失去标签编辑权限。已记录的专帖讨论区和直发频道评价正文、证明图会加入限速队列清除，老师专帖主帖改为删除提示。Telegram 对旧消息删除可能有限制，无法删除时尝试替换公开内容；权限不足或操作失败可在「发布任务」查看并重试。

「管理后台 → 设置保留天数」可设置 1～3650 天，默认 30 天，修改后对回收站内已有老师也生效。到期且公开内容清除完成后，机器人运行时自动彻底删除老师、评价、相关发布记录及关联本地证明图；仍被其他评价或草稿使用的图片保留。公开清除尚未完成或图片删除失败时保留记录，处理问题后重试。回收站可选择提前彻底删除，仍需先完成公开内容清除。删除的数据无法从回收站恢复，已有备份不会自动删除。

### 批量添加老师

集群管理员进入「管理后台 → 批量导入老师」，每行一位，每批最多 100 位，格式为「老师名称 老师用户名 老师ID」，信息用空格分隔，后两项独立可选；用户名请带 `@`：

```text
老师乙
老师丙 @teacher_c
老师丁 @teacher_d 987654321
老师戊 123456789
```

带 ID 直接绑定本人账号；只有用户名时显示“等待识别”，该用户名账号私聊机器人，或在内部查档群、指定目标群触发身份观测后自动绑定数字 ID。仅凭旧缓存不会在导入时自动授予权限。两个都不填只创建档案，以后可单独绑定。用户名不区分大小写，批次内或已有老师登记的同名用户名不能重复。绑定完成以数字 ID 为准，不随用户名被回收而转移；同一 ID 不会自动绑定第二位老师。解除本人绑定同时清除自动识别用户名，避免再次自动授权。名称中可以包含空格，末尾 `@用户名` 和纯数字会作为账号信息解析；名称本身不要以空格加纯数字结尾。旧版 `|` 和 `+` 输入仍兼容，但界面统一使用空格示例。

发送后先显示分页列表、绑定状态和总数，尚不写入数据库。确认导入整批后才统一保存，预览有效期 10 分钟；可以重新填写、取消，或发送 `/start` 放弃。名称重复、账号已被绑定、批次内重复或格式错误时提示修改，不覆盖、不自动跳过。确认时重新校验权限和冲突，任何一项失败整批不保存。老师主帖加入现有持久限速队列，不在确认时集中请求 Telegram。

绑定成功后直接显示绑定详情，包含模式、目标 ID、启用状态、队列进度，以及缺少老师或等待讨论串的说明。新增、提交、撤下、权限恢复和任务操作显示明确结果；短按钮反馈使用 Telegram 提示，错误使用警告并保留可重试页面。主菜单和管理后台显示当前可用性、发布暂停状态；草稿显示填写进度和匿名/实名状态。旧版审核区数据保留至原 72 小时到期，不自动公开；新车评不进入审核区。

主菜单和填写流程全部使用消息内按钮。按钮菜单十分钟过期，切换页面后旧按钮失效。`/start` 返回主菜单，草稿保留。有可用的直发或专帖频道即可写评。只有查档群时可以查档和查阅已有车评记录。

## 写车评

填写「老师」时可浏览列表、点击「搜索老师」，也可直接发送姓名关键词或 Telegram 用户名（带或不带 `@`）。搜索后点击老师即可回到草稿，翻页保留筛选条件。Go 版搜索和发布优先使用已绑定账号的最新观测用户名。机器人尚未记录用户名时，可在「管理后台 → 老师列表 → 老师详情 → 登记用户名」补填。老师更改 Telegram 用户名后可再次私聊机器人更新。

可从主菜单开始，也可使用 `https://t.me/机器人用户名?start=c集群编号_review_老师编号` 指定老师。例如 `start=c2_review_5` 打开集群 2 的 5 号老师。原有 `review_老师编号` 链接仍指向集群 1。

草稿字段顺序：时间、老师、出击证明、人照、颜值、身材、服务、态度、环境、综合、过程。六项评分通过按钮选择 1～10 整数；综合分自动取等权平均。时间只输入日期 `YYYY-MM-DD`，不核对预约日期，过程最多 1600 字。

点击「出击证明」后，以照片方式发送一张图片，最大 10 MB。提交前可预览车评、替换照片或在 Go 版移除照片。图片保存在数据库同目录 `proofs/` 文件夹（默认 `data/proofs/`），数据库记录随机文件名。已选照片的文件缺失或无效时，可换图或移除后提交。草稿替换的旧图片暂保留，不自动批量删除。

匿名默认开启，公开文字不显示作者一栏。实名附数字 ID、`tg://user?id=...` 身份链接和已有用户名。**上传的证明图在两种身份模式下都会公开**，请先遮挡图片中的个人信息。留名填写、核验、老师留名管理及新车评审核均已取消。Go 版必填字段齐全即可提交，间隔至少 30 秒。重复点击同一次提交不会重复生成车评。

Go 版每个目标发一条车评。带图时将完整车评放进图片说明，无图时发文字。已知的老师 Telegram 用户名独占一行，放在【老师】下方。图片说明上限为 1024 字，包含姓名、评分和编号等字段。提交前超限时草稿会保留，可缩短过程或移除照片。发布时超限会在「发布任务」标为受阻，管理员可更正正文后重试。老师专帖发到讨论串，直发发到频道，两者共用持久限速队列。历史消息保留原位置，旧队列中尚未发布的独立证明停止补发。

正式发表后客户、老师都不能修改或撤回。集群管理员在「车评处理」输入编号，可更正字段或确认撤下。撤下通过编辑公开消息为提示实现，不依赖 Telegram 对旧消息的删除能力；不再计分，巡检不会恢复原内容。管理员修改字段目前使用 JSON 输入，例如 `{"人照":8,"过程":"更正内容"}`，不允许更改老师、作者或匿名属性。撤下会把公开证明图替换为中性图片和撤下提示；本地原图保留。

每条车评综合分为六项评分的算术平均；老师综合评分为有效车评综合分的算术平均。计算保留精度，展示一位小数，同一评价多处发布只计一次。旧版人照文字记录及备份保留原综合分，不擅自转换；旧草稿需重新选择人照评分。管理员更正旧车评评分时需补充人照分数，之后自动计算综合分。

## 三种模式

- **老师专帖（可选，可多个）**：每位老师在每个频道有一条总帖和对应讨论串。写评入口使用主帖正文链接，不添加底部按钮；新版首次启动会限速更新已有主帖并移除旧按钮。新绑定从本集群补齐主帖和历史评价，按评价正文时间、记录编号从旧到新回放。
- **车评直发（可选，可多个）**：绑定后只接收新提交的评价，不全量回放历史。
- **内部查档（可选，可多个）**：只在指定群响应转发、回复、`@用户名`查询。普通用户可查，已绑定老师及集群管理员可以新增、清空标签。

频道、群不能跨绑定重复占用；专帖的关联讨论组也占用一个目标。解除绑定保留远端消息，停止同步；重新绑定专帖会补齐历史，重新绑定直发只接收之后的新车评。

“找老师”支持姓名关键词、已知绑定账号用户名搜索或输入“全部”浏览，选中老师后按评价日期从新到旧列出有效车评，每页八条。点击评价编号和日期可直达该条正文。同一车评只列一次，优先使用专帖讨论区当前副本，其次为直发频道。没有可用副本时显示「暂无可用链接」。“我的车评”按时间混排全部已通过车评，不按老师分组，每条只给一个首选有效发布链接；优先最早绑定的专帖讨论区，其次直发频道。私有频道/群链接要求用户本身有访问权限。

### 评论按钮

直发频道和老师专帖讨论区的车评共用本集群的按钮配置。带图车评在同一条消息中显示图片、评价说明和按钮，纯文字车评在正文下方显示按钮。默认带有「评价当前老师」按钮。成员点击后，机器人按车评所属集群核验成员资格，再打开这位老师的车评草稿。

集群管理员进入「管理后台 → 评论按钮」，点「＋」填写空格，或点带「✓」的按钮编辑。格子随内容扩展，最多 4 行 4 列。公开评论按格子的顺序显示，跳过空格和空行。

点进格子后，可以直接发送名称和 HTTP 或 HTTPS 链接，每项一行，也可以套用「评价当前老师」模板。保存后返回格子，可点已填按钮更改颜色。

```text
查看说明
https://example.com/reviews/{cluster_id}/{review_id}?teacher={teacher_id}
```

已有按钮可分别改名称、链接和颜色，也可清空。旧布局中藏在范围外的按钮标为「隐藏」，点「显示到评论」后才会发布。机器人会按每条车评替换链接中的集群、车评和老师编号。新车评使用最新设置。保存配置后，队列会逐条更新已发布车评原消息上的按钮。格子位置、显示状态和内容随集群 JSON 数据备份保存。

## 客户标签与权限

身份、标签、操作历史在集群内共用。保留旧版 ID / 转发 / 回复 / mention 识别及群成员观测；未见过的用户名不能凭空解析为数字 ID，隐藏来源的同名匹配不视为身份确认，用户名回收不转移旧标签。

私聊按集群授权和成员资格开放。群内仅启用服务的内部查档群响应。资料下“新增标签”发送一行标签并追加，不覆盖旧标签；“删除标签”确认后清空标签。已绑定数字 ID 的老师和集群管理员可以操作，其他人仅能查询；等待识别的用户名不授予编辑权限。操作前后均记录历史，提交时重新校验编辑权限及资料版本。升级启动及导入旧备份时清除资料和修改历史中的群备注；原有备份文件及已发送的 Telegram 消息不受影响。

superadmin 账号通过 `.env` 的 `SUPERADMIN_IDS` / `SUPERADMIN_ID` 配置，修改后重启生效。升级前请把仍需保留的旧后台管理员加入 `.env`。老师身份由管理员绑定，只授予学生标签编辑权限。

## 指定在群判定目标

集群管理员在「管理后台 → 在群判定目标」设置一个群的数字 ID 或公开用户名。目标群独立于当前查档群，也不自动启用目标群查档功能。设置时检查机器人和操作者的群管理员权限，Superadmin 直接检查机器人的权限。该设置随新版 JSON 数据备份恢复。

指定目标群会静默记录收到的发言者、入退群及成员状态事件中的数字 ID、用户名和状态；不要求同时启用「内部查档」，也不依赖专帖发布是否可用。普通消息和编辑消息可更新已知用户名，用户名更换或移除在下一次收到该用户信息时更新。仅指定目标群不会自动回复查询；只有另外启用内部查档的群才响应查档。机器人加入前的历史消息、完整成员名单以及从未出现过的潜水成员无法自动补齐。

设置后，私聊查学生和内部查档群资料卡都对该目标实时调用 `getChatMember`，显示判定群、是否在群及查询时间。`member`、`administrator`、`creator` 为在群；`restricted` 按 `is_member` 判断；`left`、`kicked` 为不在群。缺少数字 ID、权限失效、未知状态、请求失败或限流显示“无法确认”，不会拿旧缓存当实时结论，也不阻止查看原有标签。

Bot API 不能获取普通群成员完整名单，但可以按已知数字 ID 查询单个成员，不要求机器人此前见过该成员。单独输入未知用户名不能凭空解析 ID；隐藏来源的转发也可能无法确定身份。历史入群日期无法由该接口获得，只展示已观测到的入群事件时间，没有记录时显示未知。尚未设置目标时保留旧版已观测群记录展示。

## 高频路径与运行负载

群消息路由一次查询同时判断静默记录目标和查档权限；每个成员事件的身份与成员状态在同一事务内保存，避免两次独立提交。完全相同的重复事件不重写数据，真实用户名、成员状态及观测时间变化仍立即持久化。权限和实时在群结论不使用长期缓存。

新车评只为本条评价排发布任务。新绑定、重建及夜间巡检仍执行历史补齐。双文件导出直接将本地图片流式写入 ZIP，不再先构造全量 base64 图片 JSON；JPEG 使用 ZIP 存储模式，避免无效重复压缩。仍保留旧版内嵌图片 JSON 导入导出兼容路径。

启动时自动补建待办队列、未完成评论依赖、老师评价日期、作者历史、审核过期、发布位置和标签历史索引，避免已完成任务积累后仍扫描整个队列。回放与夜间排队复用已读取的评价数据，不逐条再次读取 JSON。旧审核记录清理每分钟执行一次，因此过期清理最多延后约一分钟；不改变 72 小时有效期校验。

空闲或发布暂停时，Telegram 长轮询等待 20 秒；有启用目标的待办任务时恢复 1 秒，消息到达会立即返回，不需等满 20 秒。队列在每轮轮询前处理一次，空闲夜间巡检可能比 02:30 晚最多约 20 秒启动，不改变发布限速、顺序及逐条 offset 持久化。

运行日志每约一分钟输出 `load window_s=... cpu_s=... updates=... polls=... db_changes=...`，仅包含计数、不含消息或身份内容。`cpu_s` 是该窗口进程 CPU 时间，`db_changes` 是 SQLite 累计受影响行数（包括回滚尝试），不是 SQL 次数或磁盘 I/O；可用来区分空闲轮询和消息写入负担。部署后用服务日志对照 CPU 与消息量，不应把本地基准当服务器负载降幅。

## 队列与北京时间 02:30 巡检

单进程持久队列，全局至少间隔 1.1 秒，讨论组目标至少间隔 3.2 秒。遇到 Telegram 429 按 retry_after 等待；所有批量历史同步都使用同一队列，不一口气发送。后台「发布任务」可暂停、继续、查看异常、处理发送结果不明的任务。暂停会停止发布和巡检操作，不停止私聊和审核区到期清理。

Telegram 明确返回 429 时，交互请求会按 `retry_after` 重试这一次 API 调用，不会重放整个更新，避免重复执行更新中已完成的其他操作。持久发布队列则记录限流并延后任务，不阻塞轮询；网络超时等结果不明的请求不会自动重试，发布发送会标为待核对，其他未完成操作可由用户重新发起。

机器人记录频道主帖 ID，监听 `is_automatic_forward` 获取关联讨论根消息后，才发布评论。若自动转发事件丢失，管理员可以在该绑定中登记讨论根消息；不会猜测根 ID 或发进群的普通聊天。

每天以 `Asia/Shanghai` 计算 02:30 启动时间，逐条编辑检查已登记的主帖、评论。旧版已发表评价仍保留并同步，缺少证明图的历史评价不会伪造图片。Bot API 没有任意读取频道历史的通用接口；巡检通过已存 ID 的编辑操作探测，不扫描未知人工帖子。未变更返回视为正常，不当成失败。

确认消息缺失、已知顺序错乱时，只重建该老师在该频道的主帖，评论按原始评价时间回放，更新跳转位置，不重复计分。新一代评论不覆盖旧讨论串，旧链接无法自动重定向。正文保留原始评价时间，Telegram 气泡时间是本次发送时间。权限失败、网络失败不当成消息被删。

首次启动会检查已绑定频道及讨论组权限；加入频道时向 superadmin 提示初检结果，不自动绑定或发历史。夜间任务也重新检查专帖关联和权限。权限失效时暂停相应目标，其余有效绑定继续服务。

网络超时/5xx、进程在发送期间中断时任务标为“结果不明”，不盲目重发。管理员核对后可确认未发送再重试，或登记已发送的 message_id。每一步保存进度，重启不会从头回放。相同老师的历史待处理任务阻挡更晚评论，确保恢复顺序。

巡检 02:30 只是启动时刻，大库可能持续到白天；停机错过时当日启动后补排。进度和异常在发布任务后台可见。

## 备份与恢复

集群管理员私聊「管理后台」→「导出数据备份」，收到当前集群的 JSON 数据和配套 ZIP 图片集。JSON 带有格式版本、导出时间、机器人 ID、集群编号、图片清单和批次编号。业务数据包含客户身份、标签及修改记录、老师、旧留名历史、草稿、车评状态及证明图片、绑定、主帖和评论位置、发布任务及管理操作记录。全局管理员名单仅在 Superadmin 导出时写入兼容字段，导入时不用于授权。JSON 最大 15 MB、ZIP 最大 19 MB，解压总量最大 100 MB。需要备份所有集群或超过大小限制时，用服务器 `manage.sh backup`。请一起保存 JSON 和 ZIP。

不包含 Bot Token、旧密码、旧授权和轮询 offset。使用 SQLite backup API 获取包含 WAL 的一致快照。

恢复不需要登录服务器：

1. 私聊「管理后台」→「导入数据备份」。
2. 以文件形式发送同一批的 JSON 和 ZIP，先后顺序不限，收齐并通过校验后才显示确认预览。旧版内嵌图片 JSON 继续支持单文件导入。
3. 查看校验结果、导出时间、老师/客户/车评/证明图/绑定数量。
4. 点击「确认覆盖并恢复」，或取消。确认十分钟内有效，重新 `/start` 取消待导入文件。

**导入会覆盖当前集群的整套业务数据。** 上传预览后产生的新数据也会被覆盖。数据库 schema 由程序提供，只插入经字段、类型、版本、唯一约束、外键和业务关联检查的数据，不执行文件中的 SQL。仅当前 superadmin 私聊可操作，确认时再次校验权限。请切到备份所属集群再导入。同一机器人的旧版备份导入集群 `1`。不同机器人或集群的备份，以及目标已被其他集群占用的备份，都会拒绝恢复。

确认恢复前，在当前集群数据库同级 `recovery/` 保存一组仅当前系统用户可读的原数据 JSON、ZIP 并同步落盘；保存失败则不恢复。业务数据替换在单一事务中执行，写入失败回滚。成功后尝试将原数据 JSON、ZIP 备份发到操作者私聊；发送失败会提示服务器保留路径。集群注册信息、管理群、显示名、激活状态、授权码摘要和轮询 offset 由服务器备份保存。

恢复后，该集群的绑定和发布队列暂停。请在「频道 / 群绑定」逐个检查恢复权限，核对旧快照之后的远端消息及未完成任务，最后在「发布任务」继续队列。不能通过 Bot API 自动发现所有快照之后已发出的消息；未核对就继续可能重复发布。恢复前处于请求中的任务标记为待核对，不直接重发。

备份包含客户身份、证明图和旧留名历史，文件请私密保存。新格式只接受 JSON。旧版 `.sql` 备份仍可离线恢复到单独数据库后，用新版程序导出 JSON；不要将来源不明的 SQL 在服务器执行。恢复旧 SQL 时先停止服务、另存现有数据库及 WAL/SHM，在新数据库上恢复，检查完整性后再指定 DATABASE_PATH。机器人后台不会执行上传的 SQL 文件。

## Debian 部署

```bash
cd /root/cpbot
# 创建并填好 .env 后
chmod 600 .env
bash manage.sh install
bash manage.sh logs
```

现有 `/opt/cpbot` 安装同样可用，管理脚本按实际目录生成 systemd 服务，不依赖固定安装位置。

```bash
bash manage.sh start
bash manage.sh stop
bash manage.sh restart
bash manage.sh status
bash manage.sh backup
bash manage.sh update
bash manage.sh upgrade /root/cpbot-new
```

服务器检查时间同步：`timedatectl status`。确认时钟准确、同步服务正常；应用调度始终使用 Asia/Shanghai，不要求把系统时区强改成中国。程序只允许一个进程使用同一数据库、同一 Token 不可同时启用 Webhook。

服务端 `backup` 保存部署配置和代码（含 Token）、集群注册信息、全部集群的数据库和证明图。集群 `1` 继续使用原数据库路径，其余集群存放在同级的 `<数据库文件名>.clusters/` 下。例如 `data/cpbot.sqlite3.clusters/2/` 存放集群 `2` 的数据库和证明图。服务器备份中的 `database.sqlite3` 和 `proofs/` 对应集群 `1`，`clusters/<编号>/` 对应其余集群。恢复时停止服务，按上述布局一起还原数据库和证明图后再启动。
