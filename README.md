# cpbot · 车评机器人

独立运行的人员状态与标签机器人。复用了 xcbot 的转发来源识别、成员状态判断思路，使用自己的 Token、SQLite 数据库和个人授权，没有 xcbot 的运行依赖或数据连接。

## 开始使用

需要 Python 3.9 或更新版本，使用标准库，无需安装第三方 Python 包。Linux 建议 Debian 12 / 13。

1. 将 `.env.example` 复制为 `.env`，填入独立机器人的 `BOT_TOKEN` 和总管理者的数字 `SUPERADMIN_ID`。
2. 在项目目录运行 `python3 -m cpbot`。
3. 总管理者私聊机器人发送 `/start`，点「设置密码」，发送 8～128 字符的密码。
4. 其他使用者私聊 `/start`，输入该密码后获得长期使用权限。授权绑定 Telegram 数字 ID，重启、改名或换用户名不会使授权丢失。
5. 将机器人加入需要使用的群并设为群管理员，以便接收成员事件和正常群消息、查询其他用户是否在群。

总管理者可直接使用后台，无需输入共享密码。密码只保存带随机盐的 scrypt 派生值；机器人尝试删除私聊中的密码消息。密码错误 5 次后，该账号暂停尝试 10 分钟。

## 群内查询与私聊后台

已授权者在群内转发可见来源的用户消息，或发送包含 `@用户名` 的消息，即可查询车评；文字提及用户和媒体说明中的提及也可识别。每条消息最多识别 5 个目标，同群同人 15 秒内不重复回复。未授权者的消息不会触发查询回复。匿名管理员或以频道身份发送的消息不能验证操作者，不触发查询。

群内回复是普通群消息，群成员可以看到卡片。卡片显示当前名称、Telegram ID、用户名、是否在当前群、已知入群时间、统一备注和标签。卡片下面仅有「编辑标签」「删除标签」两个按钮，分别跳转私聊编辑与删除确认。所有修改都在私聊完成，并重新验证操作者授权。直接打开链接不会获得授权。

私聊 `/start` 后可以浏览全部车评、按数字 ID / `@用户名` 查找或新增档案，也可以转发用户消息查询。编辑标签时发送两行：

```text
已核实的备注
标签一、标签二
```

第一行是备注，第二行是标签；对应行填 `-` 可清空。备注最多 500 字，标签最多 300 字。「删除标签」经确认后仅清空标签，保留备注、人员身份和历史记录。

备注和标签是同一个人的全局资料，各群共用。成员状态和入群时间按群记录；私聊资料显示最近更新的最多 8 个群，群内卡片只显示当前群。机器人在所加入的群中根据实际收到的发言、入退群消息和成员事件建立人员档案，方便后续识别 @用户名。

## 授权与修改记录

「修改记录」向所有已授权用户开放，可看全部记录，也可从某个人的资料页查看。每次人工编辑和删除标签都在同一数据库事务中保存操作人名称与 ID、时间、操作类型以及完整的修改前后内容。普通用户没有删除历史记录的入口。

总管理者在「授权管理」中查看、撤销使用者。撤销即时影响后续查询和未提交的编辑；该用户重新输入当前正确密码仍可再次获得授权。需要阻止对方重新使用时，先更换密码，再撤销其授权。更换密码不影响其他已授权者。

后台菜单与输入 10 分钟后过期；新页面会使旧页面按钮失效，重启后需重新打开后台。删除确认只能使用一次。多人同时编辑同一份资料时，后提交的旧版本会被拒绝，需重新打开资料再编辑。编辑冲突不会新增虚假修改记录。

## Telegram 提供的数据范围

- Bot API 无法用任意个人 `@用户名` 查询对应数字 ID。机器人尚未见过此人的真实用户资料时，先建立待识别档案；以后收到此人的发言、可见来源转发、成员事件或文字提及后再确认 ID。
- 机器人只能记录接入后实际收到的入群事件，无法读取完整历史入群时间或枚举全部群成员；未知字段显示「未知」。管理员升降级不会重置入群时间。
- 隐藏来源的转发无法识别真实账号，会提示改用可见来源的转发或 @用户名。频道转发不是个人身份。
- 数字 ID 是确认后的身份依据。用户名转给别人时，不转移原人员标签；若数字 ID 档案和待识别用户名档案均已有资料，分别保留，待识别档案移除用户名，仍可在列表中找到并人工核对。
- 群状态显示观测时间。Telegram 查询失败时展示已有观测，尚无观测时显示未知；转发消息本身不能证明其作者当前在群。

## Debian 后台运行

将整个项目放到 `/root/cpbot`，创建并填好 `/root/cpbot/.env` 后，以 root 执行：

```bash
cd /root/cpbot
chmod 600 .env
python3 -m unittest discover -s tests -v
cp deploy/cpbot.service /etc/systemd/system/cpbot.service
systemctl daemon-reload
systemctl enable --now cpbot
systemctl status cpbot --no-pager
journalctl -u cpbot -n 50 --no-pager
```

`DATABASE_PATH` 默认是工作目录下的 `data/cpbot.sqlite3`。`ENV_FILE` 可指定其他环境文件路径；已经设置的进程环境变量优先。服务以 `UMask=0077` 创建私有数据文件，数据库加锁防止同机使用同一数据库重复启动。这个独立 Token 应只由一个进程轮询，不能同时启用 Webhook。

备份时先 `systemctl stop cpbot`，复制整个 `data` 目录和 `.env` 到安全位置，然后 `systemctl start cpbot`。恢复时停服务、恢复这些文件，再启动。数据库保存全局档案、群状态、授权、密码派生值和修改记录，请限制备份访问。

运行日志不输出 Token、密码或原始消息内容。群回复和私聊通知发送失败时不自动重发，避免网络结果不明时重复发消息。轮询位置写入数据库；进程如果恰在修改提交后、保存轮询位置前退出，重启后消息可能重送，但私聊编辑状态已经失效，不会自动再次提交。群消息回复在这种崩溃窗口可能重复。

## 本地验证

```bash
python3 -m unittest discover -s tests -v
```

测试覆盖密码登录、权限持久化与撤销、私聊编辑与删除记录、跨群统一数据、隐藏来源、用户名回收、数据库双连接版本冲突、过期与重复按钮、成员状态和 API 查询失败。使用模拟 Telegram API，不会连接真实机器人；真实账号授权、群成员事件、链接跳转和服务运行需在填好 Token 后验收。
