# cpbot · 车评与客户查档

独立 Telegram 机器人，使用自己的 Token、SQLite 数据库和服务。与 xcbot 无数据库、接口或运行时连接。Python 3.9+，仅使用标准库。

## 开始使用

1. 将 `.env.example` 复制为 `.env`，填写 `BOT_TOKEN` 和 `SUPERADMIN_IDS`，例如 `SUPERADMIN_IDS=123456789,987654321`。旧 `SUPERADMIN_ID` 仍兼容，两项同时设置时取并集。
2. 运行 `python3 -m cpbot`。
3. 初始 superadmin 私聊 `/start` →「管理后台」→「频道 / 群绑定」。
4. 将机器人设为专帖频道管理员，授予发布、编辑消息权限；频道必须关联讨论组，机器人也必须是讨论组管理员。
5. 添加「老师专帖」绑定。检查通过后普通用户业务才开放。
6. 「添加老师」只发送一行老师名称。在「老师列表」选择老师进入详情，可修改名称、单独绑定或解除本人账号；本人账号为可选项，不影响客户写评、查评和主帖。
7. 客户填写车评并上传一张出击证明照片，提交后直接进入限速发布队列，无需审核。

### 批量添加老师

superadmin 进入「管理后台 → 批量导入老师」，每行一位，每批最多 100 位，带或不带 Telegram 数字 ID 可以混用：

```text
老师乙
老师丙 | 123456789
老师丁 987654321
```

带 ID 自动绑定本人账号，老师私聊 `/start` 后可记录用户名用于搜索；不带 ID 只创建档案，以后仍可单独绑定。名称中有空格时，建议用 `|` 分隔名称与 ID；空格后的末尾纯数字会按 ID 解析。

发送后先显示分页列表、绑定状态和总数，尚不写入数据库。确认导入整批后才统一保存，预览有效期 10 分钟；可以重新填写、取消，或发送 `/start` 放弃。名称重复、账号已被绑定、批次内重复或格式错误时提示修改，不覆盖、不自动跳过。确认时重新校验权限和冲突，任何一项失败整批不保存。老师主帖加入现有持久限速队列，不在确认时集中请求 Telegram。

绑定成功后直接显示绑定详情，包含模式、目标 ID、启用状态、队列进度，以及缺少老师或等待讨论串的说明。新增、提交、撤下、权限恢复和任务操作显示明确结果；短按钮反馈使用 Telegram 提示，错误使用警告并保留可重试页面。主菜单和管理后台显示当前可用性、发布暂停状态；草稿显示填写进度和匿名/实名状态。旧版审核区数据保留至原 72 小时到期，不自动公开；新车评不进入审核区。

主菜单和填写流程全部使用消息内按钮。按钮菜单十分钟过期，切换页面后旧按钮失效。`/start` 返回主菜单，草稿保留。没有有效专帖绑定时，普通业务停用，管理入口仍可使用。

## 写车评

填写「老师」时可浏览列表、点击「搜索老师」，也可直接发送姓名关键词或 Telegram 用户名（带或不带 `@`）；搜索后点击老师即可回到草稿，翻页保留筛选条件。用户名按已绑定本人账号的最新已知用户名精确匹配、不区分大小写；老师需先私聊机器人一次以记录用户名，更改用户名后再次私聊即可更新。未绑定账号的老师仍可按名称查找。

可从主菜单开始，也可使用 `https://t.me/机器人用户名?start=review_老师编号` 指定老师。

草稿字段顺序：时间、老师、出击证明、人照、颜值、身材、服务、态度、环境、综合、过程。六项评分通过按钮选择 1～10 整数；综合分自动取等权平均。时间只输入日期 `YYYY-MM-DD`，不核对预约日期，过程最多 1600 字。

点击「出击证明」后，以照片方式发送一张图片，最大 10 MB；文字、视频和以文件方式发送的内容不能替代。只检查收到图片并成功保存，不审核真实性或内容。提交前可重新上传替换、预览和修改草稿。图片永久保存在数据库同目录 `proofs/` 文件夹（默认 `data/proofs/`），使用随机文件名；数据库记录文件名。图片保存失败时保留草稿，不能提交。草稿替换的旧图片暂保留，不自动批量删除。

匿名默认开启，公开文字不显示作者一栏；实名附数字 ID、`tg://user?id=...` 身份链接和已有用户名。**两种身份模式都会公开证明图**，提交前应自行遮挡图片中的个人信息。留名填写、核验、老师留名管理及新车评审核均已取消。字段完整且图片已保存即可直接提交，间隔至少 30 秒；重复点击同一次提交不会重复生成车评。

发布使用两条关联消息：先完整文字车评，再发送回复该车评的证明图。老师专帖模式发到讨论串，直发模式发到频道；都使用持久限速队列。文字与图片各自记录消息位置，断线后继续任务；发送结果不明仍需管理员核对。巡检检查文字与证明图，专帖缺失会重建老师帖并从旧到新重放，保留本地图片用于再次上传。

正式发表后客户、老师都不能修改或撤回。superadmin 在「车评处理」输入编号，可更正字段或确认撤下。撤下通过编辑公开消息为提示实现，不依赖 Telegram 对旧消息的删除能力；不再计分，巡检不会恢复原内容。管理员修改字段目前使用 JSON 输入，例如 `{"人照":8,"过程":"更正内容"}`，不允许更改老师、作者或匿名属性。撤下会把公开证明图替换为中性图片和撤下提示；本地原图保留。

每条车评综合分为六项评分的算术平均；老师综合评分为有效车评综合分的算术平均。计算保留精度，展示一位小数，同一评价多处发布只计一次。旧版人照文字记录及备份保留原综合分，不擅自转换；旧草稿需重新选择人照评分。管理员更正旧车评评分时需补充人照分数，之后自动计算综合分。

## 三种模式

- **老师专帖（必选，可多个）**：每位老师在每个频道有一条总帖和对应讨论串。写评入口使用主帖正文链接，不添加底部按钮；新版首次启动会限速更新已有主帖并移除旧按钮。新绑定从全局数据库补齐主帖和历史评价，按评价正文时间、记录编号从旧到新回放。
- **车评直发（可选，可多个）**：绑定后只接收新提交的评价，不全量回放历史。
- **内部查档（可选，可多个）**：只在指定群响应转发、回复、`@用户名`查询。普通用户可查，只有全局 superadmin 可以新增、清空标签。

频道、群不能跨绑定重复占用；专帖的关联讨论组也占用一个目标。解除绑定保留远端消息，停止同步；重新绑定是新的发布副本，将重新补齐历史。

“找老师”支持姓名关键词、已知绑定账号用户名搜索或输入“全部”浏览，返回老师在各有效频道的主帖跳转链接。“我的车评”按时间混排全部已通过车评，不按老师分组，每条只给一个首选有效发布链接；优先最早绑定的专帖讨论区，其次直发频道。私有频道/群链接要求用户本身有访问权限。

## 客户标签与权限

身份、备注、标签、操作历史全局共用。保留旧版 ID / 转发 / 回复 / mention 识别及群成员观测；未见过的用户名不能凭空解析为数字 ID，隐藏来源的同名匹配不视为身份确认，用户名回收不转移旧标签。

私聊任何人可查询；群内仅指定内部查档群响应。资料下“新增标签”追加两行备注、标签（不新增某行填 `-`），不会覆盖旧内容；“删除标签”确认后清空标签，备注保留。操作前后均记录历史，提交时重新校验管理员权限及资料版本。

共享密码授权已退役，旧 grants 不再授予权限。superadmin 名单只能由现有 superadmin 修改，不能移除最后一人。每次启动会将 `.env` 中 `SUPERADMIN_IDS` / `SUPERADMIN_ID` 的 ID 补入数据库，不覆盖后台添加的管理员。从 `.env` 删掉 ID 不会撤销数据库权限；彻底撤权需在后台移除，并从配置中移除，否则重启会加回。配置变更需要重启生效，运行时仍以数据库名单校验权限。老师 Telegram 身份由管理员绑定，用于按用户名搜索；不授予管理权限。

## 指定在群判定目标

superadmin 在「管理后台 → 在群判定目标」设置一个群的数字 ID 或公开用户名。目标群独立于当前查档群，也不自动启用目标群查档功能；机器人必须是该群管理员，设置时检查权限。该设置随新版 JSON 数据备份恢复。

指定目标群会静默记录收到的发言者、入退群及成员状态事件中的数字 ID、用户名和状态；不要求同时启用「内部查档」，也不依赖专帖发布是否可用。普通消息和编辑消息可更新已知用户名，用户名更换或移除在下一次收到该用户信息时更新。仅指定目标群不会自动回复查询；只有另外启用内部查档的群才响应查档。机器人加入前的历史消息、完整成员名单以及从未出现过的潜水成员无法自动补齐。

设置后，私聊查学生和内部查档群资料卡都对该目标实时调用 `getChatMember`，显示判定群、是否在群及查询时间。`member`、`administrator`、`creator` 为在群；`restricted` 按 `is_member` 判断；`left`、`kicked` 为不在群。缺少数字 ID、权限失效、未知状态、请求失败或限流显示“无法确认”，不会拿旧缓存当实时结论，也不阻止查看原有标签。

Bot API 不能获取普通群成员完整名单，但可以按已知数字 ID 查询单个成员，不要求机器人此前见过该成员。单独输入未知用户名不能凭空解析 ID；隐藏来源的转发也可能无法确定身份。历史入群日期无法由该接口获得，只展示已观测到的入群事件时间，没有记录时显示未知。尚未设置目标时保留旧版已观测群记录展示。

## 队列与北京时间 02:30 巡检

单进程持久队列，全局至少间隔 1.1 秒，讨论组目标至少间隔 3.2 秒。遇到 Telegram 429 按 retry_after 等待；所有批量历史同步都使用同一队列，不一口气发送。后台「发布任务」可暂停、继续、查看异常、处理发送结果不明的任务。暂停会停止发布和巡检操作，不停止私聊和审核区到期清理。

机器人记录频道主帖 ID，监听 `is_automatic_forward` 获取关联讨论根消息后，才发布评论。若自动转发事件丢失，管理员可以在该绑定中登记讨论根消息；不会猜测根 ID 或发进群的普通聊天。

每天以 `Asia/Shanghai` 计算 02:30 启动时间，逐条编辑检查已登记的主帖、评论。旧版已发表评价仍保留并同步，缺少证明图的历史评价不会伪造图片。Bot API 没有任意读取频道历史的通用接口；巡检通过已存 ID 的编辑操作探测，不扫描未知人工帖子。未变更返回视为正常，不当成失败。

确认消息缺失、已知顺序错乱时，只重建该老师在该频道的主帖，评论按原始评价时间回放，更新跳转位置，不重复计分。新一代评论不覆盖旧讨论串，旧链接无法自动重定向。正文保留原始评价时间，Telegram 气泡时间是本次发送时间。权限失败、网络失败不当成消息被删。

首次启动会检查已绑定频道及讨论组权限；加入频道时向 superadmin 提示初检结果，不自动绑定或发历史。夜间任务也重新检查专帖关联和权限。已失效目标暂停；还有其他有效专帖时业务继续。所有专帖失效则停止普通业务。

网络超时/5xx、进程在发送期间中断时任务标为“结果不明”，不盲目重发。管理员核对后可确认未发送再重试，或登记已发送的 message_id。每一步保存进度，重启不会从头回放。相同老师的历史待处理任务阻挡更晚评论，确保恢复顺序。

巡检 02:30 只是启动时刻，大库可能持续到白天；停机错过时当日启动后补排。进度和异常在发布任务后台可见。

## 备份与恢复

superadmin 私聊「管理后台」→「导出数据备份」，收到带格式版本、导出时间和机器人 ID 的 `.json` 文件，以及配套 `-images.zip` 图片集。包含客户身份/标签/修改记录、老师、旧留名历史、草稿、车评状态及证明图片、管理员名单、绑定、主帖和评论位置、发布任务、管理操作记录。每次导出发送两个配套文件：JSON 数据（含图片清单及批次编号）和 ZIP 图片集（含同一批次清单）。恢复时图片写回 `proofs/`；不同批次、缺图、多图、重复或路径异常的 ZIP 会拒绝恢复，不直接解压上传文件。JSON 最大 15 MB、ZIP 最大 19 MB，解压总量最大 100 MB；超过时提示使用包含 `proofs/` 的服务器 `manage.sh backup`。即使没有图片，也保留配套 ZIP，便于完整核对。

不包含 Bot Token、旧密码、旧授权和轮询 offset。使用 SQLite backup API 获取包含 WAL 的一致快照。

恢复不需要登录服务器：

1. 私聊「管理后台」→「导入数据备份」。
2. 以文件形式发送同一批的 JSON 和 ZIP，先后顺序不限，收齐并通过校验后才显示确认预览。旧版内嵌图片 JSON 继续支持单文件导入。
3. 查看校验结果、导出时间、老师/客户/车评/证明图/绑定/管理员数量。
4. 点击「确认覆盖并恢复」，或取消。确认十分钟内有效，重新 `/start` 取消待导入文件。

**导入是整库业务数据覆盖，不是合并。** 上传预览后产生的新数据也会被覆盖。数据库 schema 由程序提供，只插入经字段、类型、版本、唯一约束、外键和业务关联检查的数据，不执行文件中的 SQL。仅当前 superadmin 私聊可操作，确认时再次校验权限。同一机器人备份可直接恢复，其他机器人 ID 的备份拒绝导入，避免沿用不属于当前机器人的消息映射。

确认恢复前，在数据库同级 `recovery/` 保存一组仅当前系统用户可读的原数据 JSON、ZIP 并同步落盘；保存失败则不恢复。业务数据替换在单一事务中执行，写入失败回滚。成功后尝试将原数据 JSON、ZIP 备份发到操作者私聊；发送失败会提示服务器保留路径。当前操作者及启动时 `.env` 管理员保留，其他管理员按备份恢复。轮询 offset 和部署配置不变，所有旧菜单失效。

恢复后，全部绑定和发布队列暂停。请在「频道 / 群绑定」逐个检查恢复权限，核对旧快照之后的远端消息及未完成任务，最后在「发布任务」继续队列。不能通过 Bot API 自动发现所有快照之后已发出的消息；未核对就继续可能重复发布。恢复前处于请求中的任务标记为待核对，不直接重发。

备份包含客户身份、证明图和旧留名历史，文件请私密保存。新格式只接受 JSON。旧版 `.sql` 备份仍可离线恢复到单独数据库后，用新版程序导出 JSON；不要将来源不明的 SQL 在服务器执行。恢复旧 SQL 时先停止服务、另存现有数据库及 WAL/SHM，在新数据库上恢复，检查完整性后再指定 DATABASE_PATH。机器人后台不会执行上传的 SQL 文件。

## Debian 部署

```bash
cd /root/cpbot
# 创建并填好 .env 后
chmod 600 .env
bash manage.sh install
bash manage.sh logs
```

现有 `/opt/cpbot` 安装同样可用，管理脚本按实际目录生成 systemd 服务，不依赖固定安装位置。

```bash
bash manage.sh start
bash manage.sh stop
bash manage.sh restart
bash manage.sh status
bash manage.sh backup
bash manage.sh update
bash manage.sh upgrade /root/cpbot-new
```

服务器检查时间同步：`timedatectl status`。确认时钟准确、同步服务正常；应用调度始终使用 Asia/Shanghai，不要求把系统时区强改成中国。程序只允许一个进程使用同一数据库、同一 Token 不可同时启用 Webhook。

服务端 `backup` 还会保存部署配置和代码（含 Token），区别于机器人内不含 Token 的数据导出。文件升级清单包含新增业务模块；保留 `.env`、原数据库及旧身份/标签/历史，使用新增表迁移，不清空旧数据。升级后旧密码编辑者失去修改权，需要 superadmin 显式加入名单。

## 验证

```bash
python3 -m unittest discover -s tests -v
```

本地模拟覆盖表单、计分、图片上传与公开发布、权限与群隔离、含图备份恢复、队列限流、结果不明、主帖丢失重建、撤下不复活及旧标签保留。真实 Telegram 的权限、自动转发根消息、公开/私有链接、实名身份链接、重启与 02:30 调度需配置独立 Token 后验收；本地测试不替代上线验证。
