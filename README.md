# cpbot · 车评机器人

独立运行的人员状态与标签机器人。复用了 xcbot 的转发来源识别、成员状态判断思路，使用自己的 Token、SQLite 数据库和个人授权，没有 xcbot 的运行依赖或数据连接。

## 开始使用

需要 Python 3.9 或更新版本，使用标准库，无需安装第三方 Python 包。Linux 建议 Debian 12 / 13。

1. 将 `.env.example` 复制为 `.env`，填入独立机器人的 `BOT_TOKEN` 和总管理者的数字 `SUPERADMIN_ID`。
2. 在项目目录运行 `python3 -m cpbot`。
3. 总管理者私聊机器人发送 `/start`，点「设置密码」，发送 8～128 字符的密码。
4. 任何人均可直接查询。需要编辑或删除标签时，私聊输入该密码后获得长期编辑权限。授权绑定 Telegram 数字 ID，重启、改名或换用户名不会使授权丢失。
5. 将机器人加入需要使用的群并设为群管理员，以便接收成员事件和正常群消息、查询其他用户是否在群。

总管理者可直接使用后台，无需输入共享密码。密码只保存带随机盐的 scrypt 派生值；机器人尝试删除私聊中的密码消息。密码错误 5 次后，该账号暂停尝试 10 分钟。

## 群内查询与私聊后台

任何人在群内转发可见来源的用户消息，或发送包含 `@用户名` 的消息，即可查询车评；文字提及用户和媒体说明中的提及也可识别。每条消息最多识别 5 个目标，同群同人 15 秒内不重复回复。查询无需密码；编辑和删除标签才需要密码授权。匿名管理员或以频道身份发送的消息不能验证操作者，不触发查询。

没有用户名的人也能查询：在群里回复其消息（例如回复「查询」），机器人按被回复者的 Telegram 数字 ID 返回车评；可见来源转发和 Telegram 的名称提及同样不要求用户名。回复普通成员的任意消息都会触发，回复机器人、匿名管理员或频道身份消息不触发该入口。查询者无需授权。

群内回复是普通群消息，群成员可以看到卡片。卡片显示当前名称、Telegram ID、用户名、是否在当前群、已知入群时间、统一备注和标签。卡片下面仅有「编辑标签」「删除标签」两个按钮，分别跳转私聊编辑与删除确认。所有修改都在私聊完成，并重新验证操作者授权。未授权者点击编辑或删除后，先输入编辑密码，验证成功后继续原操作。

私聊 `/start` 后可以浏览全部车评、按数字 ID / `@用户名` 查找或新增档案，也可以转发用户消息查询。编辑标签时发送两行：

```text
已核实的备注
标签一、标签二
```

第一行是备注，第二行是标签；对应行填 `-` 可清空。备注最多 500 字，标签最多 300 字。「删除标签」经确认后仅清空标签，保留备注、人员身份和历史记录。

备注和标签是同一个人的全局资料，各群共用。成员状态和入群时间按群记录；私聊资料显示最近更新的最多 8 个群，群内卡片只显示当前群。机器人在所加入的群中根据实际收到的发言、入退群消息和成员事件建立人员档案，方便后续识别 @用户名。

## 授权与修改记录

「修改记录」向所有用户开放，可看全部记录，也可从某个人的资料页查看。每次人工编辑和删除标签都在同一数据库事务中保存操作人名称与 ID、时间、操作类型以及完整的修改前后内容。普通用户没有删除历史记录的入口。

总管理者在「授权管理」中查看、撤销使用者。撤销即时影响后续修改和未提交的编辑，查询仍可使用；该用户重新输入当前正确密码仍可再次获得授权。需要阻止对方重新获得编辑权限时，先更换密码，再撤销其授权。更换密码不影响其他已授权者。

后台菜单与输入 10 分钟后过期；新页面会使旧页面按钮失效，重启后需重新打开后台。删除确认只能使用一次。多人同时编辑同一份资料时，后提交的旧版本会被拒绝，需重新打开资料再编辑。编辑冲突不会新增虚假修改记录。

## Telegram 提供的数据范围

- Bot API 无法用任意个人 `@用户名` 查询对应数字 ID。机器人尚未见过此人的真实用户资料时，先建立待识别档案；以后收到此人的发言、可见来源转发、成员事件或文字提及后再确认 ID。
- 机器人只能记录接入后实际收到的入群事件，无法读取完整历史入群时间或枚举全部群成员；未知字段显示「未知」。管理员升降级不会重置入群时间。
- 隐藏来源的转发按「转发自」的名称精确匹配已有档案的当前名称。仅一个同名档案时返回车评，并标明「按转发名称匹配，身份尚未确认」；不会据此绑定 ID、合并档案或创建同名身份。多个同名档案时不选择任何人，提示原消息发送者在 Telegram「设置 → 隐私与安全 → 转发消息」中允许转发链接到账号，再重新转发，或改用 @用户名。没有同名档案时也提供此操作提示。名称匹配仅覆盖机器人已有档案，不能发现未收录的同名者；改名后旧名称不再匹配。群内、私聊和后台查找中的转发均支持。频道转发不是个人身份。
- 数字 ID 是确认后的身份依据。用户名转给别人时，不转移原人员标签；若数字 ID 档案和待识别用户名档案均已有资料，分别保留，待识别档案移除用户名，仍可在列表中找到并人工核对。
- 群状态显示观测时间。Telegram 查询失败时展示已有观测，尚无观测时显示未知；转发消息本身不能证明其作者当前在群。

## Debian 后台运行

将整个项目放到 `/opt/cpbot`，创建并填好 `/opt/cpbot/.env` 后，以 root 执行：

```bash
cd /opt/cpbot
chmod 600 .env
bash manage.sh install
```

以后运行 `bash manage.sh` 打开数字菜单；也可以直接执行：

```bash
bash manage.sh start       # 启动
bash manage.sh stop        # 停止
bash manage.sh restart     # 重启
bash manage.sh status      # 查看状态
bash manage.sh logs        # 跟踪日志，Ctrl+C 退出
bash manage.sh backup      # 在线备份，无需停机
bash manage.sh update      # 从 Git 更新当前目录
```

备份保存到项目的 `backups/`，每次生成独立的 `cpbot-时间-编号.tar.gz`。包含当前代码、环境文件、SQLite 一致性快照和原路径说明；数据库快照使用 SQLite backup API，包含已提交的 WAL 数据，并检查完整性。备份含密码派生值和 Token，目录和新文件使用私有权限。脚本不会自动删除历史备份。

通过 GitHub 克隆安装后，日常更新直接执行：

```bash
cd /opt/cpbot
bash manage.sh update
```

脚本先检查当前 Git 分支已配置上游、已跟踪文件没有未提交修改，再备份、停止服务、执行 `git pull --ff-only`，检查新代码并恢复原服务运行状态。原先停止的服务保持停止。`.env`、数据和备份使用现有忽略规则保留；不执行强制覆盖或自动合并。Git 拉取失败时重新启动原先运行的服务；拉取成功但新代码校验或启动失败时保持停止，并打印备份路径，方便排查恢复。更新不会重写已安装的 systemd 服务定义。此命令需要服务器安装 Git，且新代码已推送到当前分支的上游。

如果通过手动上传文件安装，也可以继续使用目录升级，将新版完整项目上传到另一个目录，例如 `/opt/cpbot-new`，然后在旧项目执行：

```bash
cd /opt/cpbot
bash manage.sh upgrade /opt/cpbot-new
```

升级先校验新版文件、Python 语法和模块导入，再自动备份并停止服务。只覆盖明确列出的程序和说明文件，保留现有 `.env`、数据库、备份及其他文件。原先运行的服务会重新启动；原先停止的服务保持停止。复制失败或新版进程启动失败时恢复旧代码；数据库不自动回退，避免丢失升级期间的新数据。若将来的版本改变了数据库结构，需要按该版迁移说明处理兼容性。当前安装的 systemd 服务定义保持原样；需要更新服务定义时再执行 `bash manage.sh install`。

脚本报告启动成功代表 systemd 进程检查通过；请用 `bash manage.sh logs` 确认出现 `cpbot started as @...`，并在 Telegram 私聊 `/start` 检查实际可用性。

`DATABASE_PATH` 默认是工作目录下的 `data/cpbot.sqlite3`。`ENV_FILE` 可指定其他环境文件路径；已经设置的进程环境变量优先。安装脚本写入当前项目目录、Python 路径和环境文件路径。额外导出的 `BOT_TOKEN`、`SUPERADMIN_ID`、`DATABASE_PATH` 不会自动写入 systemd，部署时请把它们放进对应环境文件。服务以 `UMask=0077` 创建私有数据文件，数据库加锁防止同机使用同一数据库重复启动。这个独立 Token 应只由一个进程轮询，不能同时启用 Webhook。

恢复备份时先停止服务，将备份解压到另一个空目录，按 `manifest.json` 将 `config.env` 恢复到环境文件路径、将 `database.sqlite3` 恢复到数据库路径，并按需恢复 `source/` 的代码。恢复数据库前，先将旧数据库及其同名 `-wal`、`-shm` 文件逐个移动到单独的保留目录，避免旧 WAL 作用于恢复后的数据库；确认恢复文件权限后再启动服务。数据库保存全局档案、群状态、授权、密码派生值和修改记录，请限制备份访问。

运行日志不输出 Token、密码或原始消息内容。群回复和私聊通知发送失败时不自动重发，避免网络结果不明时重复发消息。轮询位置写入数据库；进程如果恰在修改提交后、保存轮询位置前退出，重启后消息可能重送，但私聊编辑状态已经失效，不会自动再次提交。群消息回复在这种崩溃窗口可能重复。

## 本地验证

```bash
python3 -m unittest discover -s tests -v
```

测试覆盖密码登录、权限持久化与撤销、私聊编辑与删除记录、跨群统一数据、隐藏来源、用户名回收、数据库双连接版本冲突、过期与重复按钮、成员状态和 API 查询失败。使用模拟 Telegram API，不会连接真实机器人；真实账号授权、群成员事件、链接跳转和服务运行需在填好 Token 后验收。
